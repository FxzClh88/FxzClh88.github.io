# 01 · 新版 QGC 总体架构与启动流程

> 基于 `2.0.5\source\qgroundcontrol\`（新版官方 QGC，Qt6 + CMake）

## 一、启动流程（main.cc 完整链路）

新版 QGC 的入口是 `src/main.cc`，流程非常线性：

```
main(argc, argv)
 ├─ 1. QGCCommandLineParser::parse()          解析命令行参数
 ├─ 2. Platform::initialize()                 平台初始化（各OS差异）
 ├─ 3. QGCApplication app(...)                创建核心应用类（QGuiApplication 子类）
 ├─ 4. LogManager::installHandler()           安装日志处理器
 ├─ 5. Platform::setupPostApp()               平台后置初始化
 ├─ 6. app.init()                             ★ 核心初始化（见下）
 ├─ 7. LogManager::applyEnvironmentLogLevel() 应用环境日志级别
 ├─ 8. run() 按 AppMode 分发：
 │     ├─ Test / ListTests → 跑单元测试
 │     ├─ BootTest        → 冒烟测试
 │     └─ Gui             → app.exec() 进入 Qt 事件循环 ★
 └─ 9. app.shutdown()                         清理
```

**关键点**：`app.init()` 是"初始化"，`app.exec()` 是"跑起来"。两者之间隔着一整条初始化链。

## 二、QGCApplication 的职责

`QGCApplication`（`src/QGCApplication.h`）是**整个应用的核心类**，继承 `QGuiApplication`。

全局宏 `qgcApp()` / `qApp` 被重定义指向它，所以代码里任何地方都能拿到它。

它主要负责：

| 职责       | 关键成员/方法                                                                        |
| -------- | ------------------------------------------------------------------------------ |
| QML 引擎管理 | `_qmlAppEngine`、`qmlAppEngine()`                                               |
| 主窗口缓存    | `_mainRootWindow`、`mainRootWindow()`                                           |
| 语言/翻译    | `_locale`、`setLanguage()`、`languageChanged` 信号                                 |
| 视频初始化    | `_initVideo()`、`_videoManagerInitialized`                                      |
| 根窗口初始化   | `_initQmlRootWindow()`                                                         |
| 正常启动     | `_initForNormalAppBoot()`                                                      |
| 消息弹窗     | `showAppMessage()` / `showCriticalVehicleMessage()` / `showRebootAppMessage()` |
| 缺参提示     | `reportMissingParameter()` + `_missingParamsDelayedDisplayTimer`               |
| 版本检查     | `_checkForNewVersion()`                                                        |

> ⚠️ 注意：新版 `QGCApplication.h` 里**没有直接看到 QGCToolbox 成员**（旧版有）。这说明新版弱化了工具箱单例模式，改由 QML 模块 + 单例注入承载。这一点后续会在各模块篇验证。

## 三、模块清单（36 个目录 → 分层）

`src/CMakeLists.txt` 里的 `add_subdirectory()` 就是完整的模块地图。按层次归类：

### 层次 1：入口与核心
| 目录 | 职责 |
|---|---|
| `main.cc` + `QGCApplication` | 入口 + 应用核心 |
| `LogManager` | 日志管理（含文件输出） |
| `Utilities` | 工具类（QGCLogging/QGCFileSystem/QGCNetwork 等） |

### 层次 2：协议与通信层（底层数据来源）
| 目录 | 职责 |
|---|---|
| `MAVLink` | MAVLink 协议封装、消息编解码 |
| `Comms` | 通信链路管理（串口/UDP/TCP 连接） |
| `FirmwarePlugin` | 固件差异抽象（各飞控厂商接口） |
| `AutoPilotPlugins` | 自驾仪插件（APM/PX4 等具体实现） |

### 层次 3：业务逻辑层（C++ 管理器，核心大脑）
| 目录 | 职责 |
|---|---|
| `Vehicle` | **载具抽象**（无人机/车/船/潜水器的统一模型，最核心） |
| `MissionManager` | 任务管理（航点/任务的收发） |
| `FactSystem` | **事实系统**（飞控参数的统一抽象层） |
| `PositionManager` | 位置管理（自身 GPS 定位） |
| `VideoManager` | 视频管理（图传接收/渲染） |
| `Camera` | 相机控制 |
| `Gimbal` | 云台控制 |
| `FollowMe` | 跟随模式 |
| `Joystick` | 摇杆输入 |
| `ADSB` | ADS-B 空中交通避让（附近飞机） |
| `GPS` | GPS 处理 |

### 层次 4：地图与地形
| 目录 | 职责 |
|---|---|
| `FlightMap` | 飞行地图（地图控件、航迹显示） |

### 层次 5：UI 层（QML，三大视图 + 支撑）
| 目录 | 职责 |
|---|---|

| `PlanView` | **规划视图**（任务规划、航点编辑） |

## 四、构建/模块组织方式（新版 vs 旧版的关键差异）

新版用 **CMake + QML 模块 URI 命名空间**，每个目录是一个独立 STATIC 库 + 一个 QML 模块：

```
qt_add_library(FlyViewModule STATIC)               # 独立静态库
qt_add_qml_module(FlyViewModule                    # QML 模块
    URI QGroundControl.FlyView                      # 命名空间 URI
    QML_FILES FlyView.qml ...                       # 该模块的 QML 文件
    NO_PLUGIN
)
```

所以新版 QML 里的引用是 `import QGroundControl.FlyView`，而**旧版**是 `.qrc` 资源文件 + 路径引用。这是 HTML 报告里"QML 模块化"迁移难点的根源。

## 五、架构分层总图

```
┌─────────────────────────────────────────────────────┐
│  UI 层 (QML, 模块URI: QGroundControl.*)             │
│  MainWindow → FlyView / PlanView / AnalyzeView      │
│            + Toolbar + QmlControls + Viewer3D       │
├─────────────────────────────────────────────────────┤
│  业务逻辑层 (C++ 管理器)                            │
│  Vehicle · MissionManager · FactSystem ·            │
│  VideoManager · Camera · Gimbal · PositionManager   │
├─────────────────────────────────────────────────────┤
│  协议/通信层 (C++)                                  │
│  MAVLink · Comms · FirmwarePlugin · AutoPilotPlugins│
├─────────────────────────────────────────────────────┤
│  基础设施层                                         │
│  Utilities · Settings · AppSettings · LogManager    │
└─────────────────────────────────────────────────────┘
```

数据流向（读一遍就懂全局）：

```
飞控 ⇄ Comms(链路) → MAVLink(协议) → Vehicle(载具模型)
                                      ↓
                        FactSystem(参数) / MissionManager(任务)
                                      ↓
                            QML UI 层展示 (FlyView/PlanView...)
```
