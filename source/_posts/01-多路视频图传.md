# 01 · 多路视频 / 图传系统（12 路）

> 基于旧版 `2.0.5\source\flyerlink\src\VideoManager\VideoManager.h` + `src\VideoReceiver\`
> ⚠️ 这是 FlyerLink **最深度的 C++ 定制**，也是迁移难度最高的一处（当前 diff 中未迁移）。

## 一、模块概览

官方 QGC 原生只支持 1-2 路视频（主图传 + 热成像）。FlyerLink 把它扩展成 **12 路图传**，用于多机/多传感器场景（普通镜头、热成像、水下多相机等）。

## 二、12 路架构（VideoManager.h）

### 2.1 核心：12 个 VideoReceiver 数组

```cpp
int videoCounts = 12;                       // 图传数量
VideoReceiver* _videoReceiver[12];          // 12 个接收器
void*          _videoSink[12];              // 12 个视频 sink
QString        _videoUri[12];               // 12 路 URI（RTSP）
bool           _videoStarted[12];           // 12 路启动状态
bool           _lowLatencyStreaming[12];    // 12 路低延迟标志
```

每一路视频都是独立的一组状态。官方原版是单个 `_videoReceiver`，FlyerLink 改成数组。

### 2.2 12 个 Q_PROPERTY（暴露给 QML）

| 路数 | 属性名 | 备注 |
|---|---|---|
| 1 | `videoReceiver` | 主图传 |
| 2 | `thermalVideoReceiver` | 热成像 |
| 3 | `thirdVideoReceiver` | 第三路 |
| 4 | `fourthVideoReceiver` | 第四路 |
| 5-8 | `fiveVideoReceiver` ~ `eightVideoReceiver` | 注释「第5-8路图传」 |
| 9-12 | `nineVideoReceiver` ~ `twelveVideoReceiver` | 注释「第9-12路图传」 |

QML 里直接 `videoManager.thermalVideoReceiver` 就能拿到第 2 路，绑定到显示控件。

### 2.3 12 路 RTSP URL 槽

```cpp
void _rtspUrlChanged();    // 第1路
void _rtspUrl02Changed();  // 第2路
...                        // 一直到 _rtspUrl12Changed()
```

**每路视频用独立 RTSP URL 配置**（网络视频流）。URL 变了就重启那一路（`_restartVideo(id)`）。

### 2.4 关键方法：bindVideoSink

```cpp
public slots:
    void bindVideoSink(QObject* sinkItem, int streamIndex);  // "sink调取"
```

把第 `streamIndex` 路的视频**绑定到某个 QML 显示控件**。这是"多路视频显示在不同窗口"的关键——每个显示控件 bind 一路。

## 三、技术栈（三种后端）

| 后端 | 属性 | 用途 |
|---|---|---|
| GStreamer | `isGStreamer` | **主后端**，GstVideoReceiver + 自定义 gstqgc 插件 |
| UVC | `isUvc` / `uvcVideoSourceID` | USB 摄像头 |
| Taisync | `isTaisync` | 图传品牌（专用链路） |

`VideoReceiver/` 目录里有 `GstVideoReceiver.cc`、`gstqgc.c`、`gstqgcvideosinkbin.c` —— 这是**旧版基于 GStreamer 的自定义视频解码管道**。

## 四、视频接收器接口（VideoReceiver.h）

抽象基类，核心操作：

| 方法 | 用途 |
|---|---|
| `start(uri, timeout, buffer)` | 开始接收（uri 就是 RTSP 地址） |
| `stop()` | 停止 |
| `startDecoding(sink)` / `stopDecoding()` | 绑定/解绑显示 sink |
| `startRecording(file, format)` / `stopRecording()` | 录像（MKV/MOV/MP4） |
| `takeScreenshot(file)` | 截图 |

## 五、迁移难点（重点）

**旧版（Qt5 + GStreamer）→ 新版（Qt6 + QtMultimedia）的鸿沟：**

| 维度 | 旧版 FlyerLink | 新版 QGC |
|---|---|---|
| 解码后端 | GStreamer（自定义 gstqgc 插件） | QtMultimedia / UVC / 多后端抽象 |
| 接收器数量 | 12 路写死在 VideoManager | 抽象基类 + 动态管理 |
| 视频源 | RTSP URL 数组 | VideoSource 抽象 |

**迁移要做的事：**
1. 把 GStreamer 的 `gstqgc` 自定义插件逻辑，用 QtMultimedia 重新实现（或保留 GStreamer 后端但适配 Qt6）
2. 12 路接收器的管理逻辑（数组 + bindVideoSink）要适配新版的 VideoReceiver 抽象
3. 新版有 4 个 `FlightDisplayView*.qml`（QtMultimedia/UVC/Video/VideoOutput），要选对后端承载 12 路

> 这是 HTML 报告里"🔥🔥🔥🔥🔥"最高难度模块的原因。

## 六、数据流

```
RTSP 视频源（12 个地址）
  → VideoReceiver[0..11]（GStreamer 解码）
  → _videoSink[0..11]（绑定到 QML 控件）
  → QML 显示（12 个视频窗口）
```
