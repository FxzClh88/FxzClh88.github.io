# Flyerlink 地面站测试清单

> 基于 QGC v5.0.3 二次开发版本 · Flyerlink 阶段性验收测试
> 文档版本：v1.0 ｜ 编写日期：2026-08-21

---

## 1. 文档说明

### 1.1 适用范围
本清单适用于 **Flyerlink**（基于 QGroundControl v5.0.3 二次开发的地面站）阶段性开发完成的验收测试，覆盖 **Flyerlink 全部定制功能** 与 **原版 QGC 核心功能** 的重点回归。

### 1.2 测试平台
- 操作系统：Windows 11（主测平台，可扩展至 macOS/Linux）
- 构建配置：CMake + Qt 6.11，应用名 `FlyerLink` / 构建名 `Flylink`
- 品牌色：#0080FF

### 1.3 标注图例

| 标记 | 含义 |
|---|---|
| 🔴 必须真机 | 强依赖物理硬件或飞控 ACK 反馈，必须接真实设备测试 |
| 🟡 可选（建议真机） | 纯软件可跑主流程，但接真机验证更充分 |
| 🟢 可脱硬 | 纯软件即可测试（MockLink 模拟 / SITL / 日志回放 / 模拟数据源） |

| 优先级 | 含义 |
|---|---|
| **P0** | 必测，验收阻塞项（定制功能 + 核心安全功能） |
| **P1** | 应测，核心主流程回归 |
| **P2** | 可选，边缘场景 / 性能 / 兼容性 |

### 1.4 术语表
- **MockLink**：QGC 内置的纯软件模拟飞控链路，可模拟遥测、参数、任务、FTP、相机、云台、校准等全流程，无需任何硬件。
- **SITL**：软件在环仿真（ArduPilot SITL / PX4 jMAVSim），飞控固件在 PC 上运行，通过 UDP 14550 与地面站通信。
- **tlog / qlog**：飞行日志文件（通信日志 / 飞行数据日志），可用于日志回放。
- **ROV**：遥控水下机器人（Flyerlink 的深度图、声呐、DVL、3D 模型功能面向 ROV 场景）。

## 4. 分模块详细用例

### 模块 A — 连接与通信

#### A1 串口连接与断线重连 🔴 P1
| 项目 | 内容 |
|---|---|
| 前置条件 | 飞控 + USB 数传已连接电脑；设备管理器可看到 COM 口 |
| 操作步骤 | 1. 打开「通信连接」设置 → 添加串口连接，选择对应 COM 口与波特率（常见 57600/115200）<br>2. 点击连接，观察状态<br>3. 连接成功后**拔掉 USB 线**，观察应用行为<br>4. 重新插回 USB 线 |
| 预期结果 | 2. 连接成功，遥测数据开始刷新，状态栏显示已连接<br>3. 应用在数秒内检测到断链并弹出断链告警，状态栏切为"未连接"；**不崩溃、不卡死**<br>4. 可手动或自动重连成功，遥测恢复 |
| 备注 | 断链告警属安全功能，属 P0 范畴，若此用例资源紧张至少验证断链告警部分 |

#### A2 UDP 链路（MockLink / SITL） 🟢 P0
| 项目 | 内容 |
|---|---|
| 前置条件 | 无需硬件；可选用 ArduPilot SITL 或直接使用内置 MockLink |
| 操作步骤 | 1. 打开「通信连接」→ 添加 UDP 连接（默认端口 14550）<br>2. 启动 MockLink 模拟连接（或启动 SITL 仿真）<br>3. 观察应用自动/手动连接状态<br>4. 断开 SITL 进程，再重新启动 |
| 预期结果 | 2-3. 连接成功，遥测（姿态/位置/电压）正常刷新<br>4. 断开后应用显示断链；SITL 重启后可通过自动重连恢复 |
| 备注 | UDP 14550 自动连接为 QGC 标准行为，是全流程纯软件验证的基础链路 |

#### A3 TCP 链路 🟢 P1
| 项目 | 内容 |
|---|---|
| 前置条件 | 一个可提供 TCP MAVLink 数据源的进程（可用 SITL 或自写 TCP 转发） |
| 操作步骤 | 1. 「通信连接」→ 添加 TCP 连接（地址 127.0.0.1，端口如 5760）<br>2. 启动 TCP 数据源并连接<br>3. 断开数据源进程 |
| 预期结果 | 2. 连接成功，遥测正常<br>3. 断链告警正常出现，应用无异常 |
| 备注 | 若具备网络数传设备（WiFi 数传），可用真实 TCP 链路做 🔴 补充验证 |

#### A4 USB 直连飞控 🔴 P1

|---|---|
| 前置条件 | 飞控 USB 口直连电脑（Pixhawk 类标准 USB 接口） |
| 操作步骤 | 1. 插入 USB，确认系统识别新设备<br>2. 应用内通过 USB 串口链路连接<br>3. 观察连接稳定性（保持连接 10 分钟） |
| 预期结果 | 1-2. 识别正常、连接成功、遥测稳定刷新<br>3. 10 分钟内无意外断连，无数据中断 |
| 备注 | 与 A1 类似但走 USB 直连通道，验证不同接线方式 |

#### A5 蓝牙链路（BLE / 经典） 🔴 P2

## 5. 风险与注意事项

### 5.1 物理安全风险（🔴 真机用例）
1. **Arm/起飞/降落/返航/Orbit/模式切换/任务执行（C2-C5、C9、C10）为高危项**：必须在室外开阔合规场地、系留平台或无桨测试台执行；带桨测试必须双人确认 + 遥控器随时接管 + 急停预案。
2. 真机测试前确认：电量充足、GPS 信号良好、场地净空、无人群、符合当地法规（飞行许可）。
3. 任何异常立即执行：RTL（返航）→ 手动接管 → 急停。

### 5.2 授权与合规
- 图传/数传频段使用需符合当地无线电管理要求。
- RTK/NTRIP 服务使用需账号授权。
- 固件升级前**备份全部参数**，避免升级失败导致配置丢失。

### 5.3 数据风险
- 任务上传（D5）会**覆盖飞控已有航线**，操作前备份。
- FTP/日志操作（E7/F 组）避免误删重要文件。
- 日志文件建议按"日期+机型+场景"命名，便于追溯。

### 5.4 执行顺序建议
1. **冒烟测试集**（3.1 节，P0 + 🟢 项）→ 确认主链路无阻塞
2. **🟡 可选真机项**（B5/B6/D6/G9）
3. **🔴 真机项**：先软件/模拟链路项（如 D5 先 MockLink），再高危飞行项（C 组放最后集中执行）
4. 每模块测试截图留证，P0 项全部通过后才可进入验收结论

### 5.5 回归建议
- Bug 修复后复测关联用例（用例备注中的关联项）。
- 每次发版必跑：B 模块全部 + 冒烟测试集。
- 建议将本清单中 🟢 可脱硬用例逐步固化为自动化测试（现有 Qt Test 体系 test/ 目录），定制功能目前均无自动化覆盖。

### 5.6 已知测试盲区提示
- **新定制功能无自动化测试**：KeyboardController、UdpSender、Sidebar、DepthMap、DvlSonar、VirtualController、3D 模型、13 项 AppSettings 均无对应单测，本次人工测试清单已覆盖，后续建议补自动化。
- **Zeroconf 自动发现**：仅保留设置开关（autoConnectZeroConf），LinkManager 无实际实现，如非本期目标可标注"暂不测"。
- **UdpSender**（src/QmlControls/UdpSender.cpp）为新增 UDP 发送器，建议补充专项验证其数据发送正确性（可作为 B 模块补充用例）。
