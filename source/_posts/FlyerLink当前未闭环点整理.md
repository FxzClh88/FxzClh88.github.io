## 四、详细问题与建议

验收标准：

### 2. 12 路视频已完成骨架，但未完成运行验收（P0）

当前已实现：

- `MultiVideoSettings`：12 路 URI、通道开关、总开关、并发限制及 JSON 导入/导出。
- `MultiVideoManager`：12 个独立会话、通道启停、并发闸、原生单路视频互斥。
- `ChannelSession`：GStreamer 管线、首帧检测、帧心跳、断流重建、指数退避和退出清理。
- `ChannelSourceFactory`：RTSP、UDP、TCP、HTTP(S) 的 H.264 源段。
- `MultiVideoGridView.qml`：动态网格、通道状态、协议标签、性能信息和窗口/全屏/浮窗模式。
- 设置页、侧边栏入口、QML 全局单例和应用退出清理。

仍需处理：

- H.265 分派尚未实现。
- RTSP `tcpudp` 当前没有真正实现 TCP/UDP 回退组合。
- 点击通道后的主画面放大/PIP 行为仍是预留入口。
- 持久化的 `masterEnabled` 与 `MultiVideoManager::enabled` 启动初值需要验证，避免重启后设置显示开启但引擎仍关闭。
- 需要验证多路模式关闭后官方单路视频能否稳定恢复。
- 需要验证无流、坏地址、频繁切源、应用退出及 QML 页面重建场景。

最低测试矩阵：

| 场景 | 验收内容 |
|---|---|
| 1 路 RTSP | 首帧、持续播放、切换开关、退出 |
| 4/6 路混合协议 | RTSP/UDP/TCP 并存，独立断流不影响其他通道 |
| 12 路压力 | CPU、GPU、显存、内存、网络带宽、QML 帧率 |
| 断流恢复 | 拔网、服务端停流、重新推流后的恢复时间 |
| 配置变更 | 单通道换 URL、禁用、重新启用、JSON 导入 |
| 模式切换 | 官方单路与多路模式反复切换 |
| 退出清理 | 播放状态下关闭程序，无崩溃、卡死或残留线程 |

### 3. 虚拟遥控模式逻辑不完整（P0）

`App.SettingsGroup.json` 将 `virtualController` 定义为 `uint32` 枚举：

- `0`：None
- `1`：游戏手柄
- `2`：虚拟摇杆
- `3`：键盘

但当前 `VirtualController.qml` 中：

- None 判断和写入使用字符串 `"none"`。
- 游戏手柄、虚拟摇杆、键盘均判断并写入数值 `0`。
- 游戏手柄分支直接访问 `globals.activeVehicle`，没有空载具保护。

建议按 `0/1/2/3` 修正绑定，并明确每种模式切换时需要关闭的其他输入源。键盘模式如果尚无键盘事件映射，应明确标记为未实现，避免只显示配置入口。

验收标准：四种模式可以互斥选择、重启后保持、无载具时不会报错，并能实际控制对应输入源。

### 4. 多设备图标资源路径不一致（P1）

当前 C++ `FirmwarePlugin::vehicleImageOpaque()` 返回 `/qmlimages/custom*.png`，与 FlightMap CMake 资源前缀一致；但 `VehicleMapItem.qml` 又重复判断载具类型并返回 `/res/custom*.png`。

建议删除 QML 重复判断，统一使用 `vehicle.vehicleImageOpaque`；或者给 `/res` 资源显式设置正确 alias。优先推荐统一由 C++ 决策，避免两套载具类型逻辑继续漂移。

验收标准：固定翼、VTOL、车、船、潜水器和默认多旋翼均可在地图上正确显示图标。

### 5. ROV 三维模型仍需交互和姿态校验（P1）

当前已经具备模型路径、颜色、初始旋转和实时姿态绑定，但存在以下问题：

- 侧边栏 `Modul3D` 项的 `enable` 为空，单击只切换图标颜色，没有写入 `view3DStatus`。
- `eulerToQuaternion()` 计算得到 `x/y/z/w` 后调用 `Qt.quaternion(x,y,z,w)`；需要按照 Qt 的四元数参数定义核实标量位置。
- `180-yaw`、roll/pitch 负号及不同 `.mesh` 模型初始朝向需要使用真实 ROV 校准。
- 外部文件路径在 Windows、Android 等平台的可访问性和持久化需要验证。

验收标准：侧边栏状态与模型显示一致；真实设备做 roll/pitch/yaw 时模型方向正确；重启后路径、颜色和偏移保持。

### 6. 水下 UDP 控制缺少工程化能力（P1）

当前 `DvlSonar.qml` 已能发送 DVL/声纳文本命令和带 CRC 的十六进制数据，但设备地址 `192.168.2.2:55556` 固定写在 QML 中，发送接口没有返回结果或错误状态。

建议：

- 将设备 IP、端口和协议参数移入 SettingsGroup。
- 为发送失败、非法地址和非法端口提供 UI 提示。
- 如载荷协议支持，增加 ACK、超时和重试。
- 明确 `sendHexUdp` 自动追加 CRC 是否符合所有手动调试场景。

验收标准：地址可配置；网络异常时有明确提示；DVL/声纳状态与载荷实际状态一致。

### 7. 测试和回归证据不足（P1）

当前构建目录表明 Windows Debug 可执行文件已成功生成，但 `LastTest.log` 没有实际测试用例结果，也没有多视频、水下设备或 ROV 姿态的运行记录。

- ChannelSourceFactory 的 URL 解析测试。
- MultiVideoManager 的启停、并发限制和单路互斥测试。

- 真实视频源、DVL/声纳和 ROV 姿态的联调记录。
- 官方核心功能回归：连接飞控、地图、多载具、任务规划、相机、摇杆和日志分析。
